# 6. Коментари

## 6.1 Защо, а не какво

Коментарът не трябва да повтаря какво прави кодът – това се вижда от самия код. Коментирайте само неочевидните неща: защо нещо е направено точно така.

```cpp
// Лошо
i++; // увеличаваме i с 1

// Добре
// Достатъчно е да проверим делителите до корен от числото,
// защото всеки по-голям делител има двойка, по-малка от корена.
for (int i = 2; i * i <= number; i++) {
```

## 6.2 Кодът обяснява себе си

Ако имате нужда от коментар, за да обясните какво съдържа променливата или какво прави функцията, по-добре сменете името ѝ.

```cpp
// Лошо
int c; // брой на положителните числа

// Добре
int positiveCount;
```

## 6.3 Без закоментиран код

Не оставяйте стар код, превърнат в коментар. Той затрупва програмата и обърква читателя дали е нужен, или не. Ако кодът не се използва, изтрийте го – предишните версии остават в историята на Git.

```cpp
// Лошо
int sum = a + b;
// int sum = 0;
// sum = sum + a;
// sum = sum + b;
cout << sum;
```
